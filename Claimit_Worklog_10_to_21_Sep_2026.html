10 – 13 September  DEVELOPMENT

Grouped, not split by day — the individual completion dates were not logged. Every item below was delivered within this window.

Claimit Privilege — new feature, built end to end

  • 5 app screens: home with 9 category tiles and live counts, partner list, partner detail, pass generation, approval
  • Backend: 9 categories, partner search with three sort modes, coverage counts, 10-minute pass with CLM-XX-nnnnnn reference, approval endpoint, redemption history
  • Self-listing flow for businesses (photo upload, pending status)
  • Admin: full CRUD, bulk upload with template and parser, redemption history view
  • Database indexes: 2dsphere for location, unique reference, user history

Rewards made admin-configurable

  • Cashback percentage and reward-point rate moved out of code into admin settings
  • Monthly scan-count tiers — cashback rises with usage (0 / 15 / 50 scans), capped at 5%
  • Counted from permanent bill history rather than the 24-hour scan cache, so the tier is accurate
  • Admin validation rejecting invalid tier ladders

  • "Never show empty" — nearest-content fallback applied across five feature pages
  • Claimit Select coverage screen: professional counts by city and category
  • WhatsApp user-acquisition campaign, with cashback and reward-point figures pulled live from admin settings so the message can never promise an amount the wallet won't pay

14 September  INCIDENT

WhatsApp delivery failure — diagnosis

  • Bulk sends of 300, 50 and 3 messages all failing; OTP delivery also failing
  • Traced to Twilio error 63038 — a 50-message daily cap applied to the whole account, not the campaign
  • Established the account was paid and active, so the cap was an anti-fraud restriction triggered by a burst of template messages to cold numbers, not a trial limit
  • Found a second, separate fault: /auth/send-otp returned 200 OK and "OTP sent" even when Twilio rejected the message — users saw success and no code arrived
  • Confirmed Meta/WhatsApp side was healthy (sender Online, quality High, 80 MPS) — ruling out two earlier incorrect theories

15 September  CRITICAL INCIDENT

Ransomware attack on the production database, discovered this day. MongoDB was reachable from the public internet on port 27017 and, although an admin user existed, authorization was never enabled in the configuration — so the password was never checked. An automated bot deleted every collection and left a database named READ_ME_TO_RECOVER_YOUR_DATA demanding 0.0065 BTC. No ransom paid.

Response

  • Attack identified and distinguished from the "missing data" symptom the client first reported
  • 250 MB backup located on the server and copied off it
  • Port 27017 closed at the firewall
  • Database restored from the 17 August backup — 25 users, 1,052 shops recovered
  • MongoDB bound to 127.0.0.1 and authentication enforced; verified that anonymous access is now refused
  • New 32-character password generated on the server, written to config, never displayed
  • mongodump backups scheduled every 3 days with automatic rotation, and a test-restore proving the archive works
  • Incident and recovery documented for the client
Data loss: the newest backup available was 17 August. Records created between 17 August and 15 September could not be recovered.

16 September  RESTORATION

  • Admin website loading but showing no data — traced through Firebase Hosting → CloudFront → EC2
  • Found three backends running, not two. The admin panel is served by port 8002; ports 8000 and 8001 are separate services. Earlier checks had been run against the wrong one, which is why it appeared healthy while the panel stayed broken
  • Corrected the admin backend's database connection and credentials
  • Images failing app-wide — traced to AWS having deleted the IAM access key (it was published in a git repository). New credentials issued and installed across all backends
  • Claimit Privilege cards redesigned to match Claimit Select exactly — same padding, photo size, typography and button layout
  • Server operations guide written for the client

18 September  INFRASTRUCTURE DEVELOPMENT

AWS network

  • Reduced from five ports open to the entire internet down to two that must be public
  • SSH restricted to a single IP address
  • Dead port 8000 closed and its service retired
  • Confirmed only one security group is attached, so the restrictions actually take effect

Process management — root cause of repeated outages

  • Discovered two process managers (systemd and PM2) both starting the same two applications. At every boot they raced for the same ports; the loser crash-looped — over 2,200 restarts observed
  • This was the underlying cause of the "orphan processes" that had recurred all week
  • PM2 removed and disabled; systemd left as the single owner
  • Services ordered to start after the database, fixing a start-up race
  • Pending OS security updates applied; reboot performed and recovery verified twice, unattended

App — location switching

  • Found that screens loaded data once and never refreshed when the user changed location — the header updated, the content did not
  • Found a second, worse fault: several screens read the city saved on the account at registration rather than the location the user had picked, so they could never respond to the picker at all
  • Built a shared mechanism so any screen refetches on location change, and applied it to Select, Privilege, Reward Zone, Deals, Search and Notifications
  • Added the missing back button to Claimit Privilege

19 September  DATA INTEGRITY

174 businesses were invisible to every user. Bulk-uploaded records saved without map coordinates are not returned by a location search at all — they import cleanly, appear in the admin panel, and no customer can ever reach them. Local Finds was 100% invisible (95 of 95); Claimit Select was 67% invisible (79 of 118).
  • Built an audit tool reporting, per feature: total records, how many are findable, which pincodes the invisible ones belong to, swapped or zeroed coordinates, and index health
  • Confirmed Claimit Privilege was unaffected (157 of 157 findable) — it was the one importer that already handled this correctly
  • Made coordinates mandatory on bulk upload across shops, Select and Local Finds: a row without them is now rejected with the row number and reason, exactly like a missing phone number
  • Validation also catches coordinates entered in the wrong order and 0,0 defaults
  • Upload templates corrected — the columns had been described as optional

Deal landing page image carousel

  • Admin upload interface for the extra photos, shown only for deal-type ads
  • Carousel on the deal landing page matching the shop page — swipe, auto-advance, position dots
  • Built so deals with a single image are visually unchanged, and existing deals need no migration
